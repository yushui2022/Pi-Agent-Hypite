# Pi Studio Workers 执行基线

2026-10-19，依据用户批准的六阶段执行规划。本文优先于旧容器/单机部署规划。

## 目标与边界

网页完成参考导入、素材映射、分析改编、方案确认、批量制作、局部修改及下载。所有自研云端服务使用 Cloudflare Workers；允许 R2、D1、Workflows、Queues、Durable Objects、Cloudflare 基础 Media Transformations 与外部模型 API。不部署容器，不默认使用完整第三方剪辑平台。

沿用现有原生 JavaScript 前端，新云端代码使用 TypeScript。保留 Pi Agent 源码核心；独立实现视频工程和媒体执行，不复制 Hypit 受限制源码，也不让现有 vendor/hypit 成为新 SaaS 运行依赖。旧本地工具仍保留。

## 首版规格

- 15 秒，720×1280，25 fps，H.264/AAC MP4；1–3 镜头硬切、一条主画面轨。
- 固定样式字幕最多两行，烧录进成片；配音和背景音乐各一条，固定音量、首尾淡入淡出。
- 每批 1–20 变体；账号数量不作为生产限制。
- 云端新输入：H.264 MP4，小于 100 MB、不超过 60 秒；JPEG/PNG。历史其他格式只保留查看，不暗示可制作。
- 邀请内测；暂不做支付、自由多轨、复杂转场、任意代码、动态逐字字幕、精准换脸换物、长视频或自动发布。

## P0 执行顺序

1. 独立实验与合成素材，保持现有 4320 工作台及用户数据不变。
2. 审计单线程 FFmpeg Wasm 的导入、许可证、内存与能力；自建预编译 Wasm 适配，先评估可用核心，再收敛精简构建。
3. 同规格拼接→单镜头字幕/配音/音乐→三镜头 15 秒；每镜头单独编码，中间结果持久化，最后尽量 remux。
4. Pi 核心使用显式模型传输、白名单工具和持久化检查点，验证错误工具拒绝与新实例恢复。
5. 配置真实 Cloudflare 后验证基础媒体转换与完整媒体执行，收集 CPU、Wasm/缓冲与总内存证据、费用和输出检查。
6. 连续 20 次基准，无内存/CPU 超限，保留余量；时长误差≤1 帧，字幕烧录、音轨连续且音画同步。形成 P0 关口报告。

## 契约与风险

媒体仅通过资源引用流转，不进入对话、数据库正文或队列。执行冻结工程/模型配置，稳定幂等键覆盖提交、付费调用及归档。权限来自服务端会话，Agent 同样受限；不开放 Shell 或用户代码。

本地账号/项目/素材/方案/批次已存在，真实生成与公网尚未交付。现有执行接口继续明确未开放，直到真实媒体关口通过后再改异步任务提交。云账号、模型配置和测试预算尚未落实，本规划不代表开通服务或授权付费。

主要风险：Wasm 编码内存/CPU、中文字体与字幕、AAC 拼接时间戳、Cloudflare 媒体能力边界、Pi 验证器运行时兼容、供应商未知状态导致重复付费、密码运算内存、跨租户资源访问。各项必须通过相应实测，不以启动检查代替。

中间产物位于 G:/DevCache/Temp/pi-agent-hypite/workers-p0，长期样片可归档项目 output。缓存不包含可自动删除的用户原素材或成片。
