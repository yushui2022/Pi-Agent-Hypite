# 本地创作准备完善（2026-10-19）

用户暂未提供 Cloudflare 账号，继续完善既有本地工作台。本轮提供方案/批次规格检查、基于旧批次创建新版本，以及素材损坏后的重新导入修复。不是 P0 云端放行，也不是 P1–P5 制作引擎或云端迁移交付；`execute` 仍返回 409。

## 使用路径

1. 打开项目的「替换方案」，保存修改，再点「检查已保存方案」。
2. 查看需修改事项、提醒和主画面时间安排；可定位替换位置或打开素材页，并下载 JSON 检查报告。
3. 「制作批次」内点「检查此批次」，检查的是该批次保存时的方案和变体，不受后来编辑的当前方案影响。
4. 点「基于此批次新建」，带入旧方案与各版本的素材、文案；可以复制单个版本、改文案或素材、移除版本，然后保存为新批次。新批次显示来源，旧批次不修改。
5. 检查发现文件缺失或大小变化时，重新导入原文件。上传后比对完整 SHA-256，恢复到原素材 ID，所有方案/批次引用继续有效。

## 规则与边界

| 内容 | 当前实现 |
| --- | --- |
| 输出目标 | 检查基准为 15 秒、720×1280、25 fps；这不是实际编码或成片验证 |
| 时间线 | 0–15 秒、0.04 秒帧边界；主画面最多 3 镜头、无重叠；未标注区间提醒用户确认保留参考还是补素材 |
| 字幕 | 非空、最多 2 行、每行最多 15 字符、单轨无重叠；按本地实验固定字体范围检查字符，实际字形与烧录仍待媒体执行验证 |
| 素材 | 核对引用、类型、文件存在及大小；视频非 MP4 或文件达到 100 MB 时提示不符合首版范围。MP4 扩展名不证明 H.264，仍待真实探测/解码 |
| 音频 | 最多两项；提醒当前替换表未区分配音/BGM 用途、增益与淡入淡出参数 |
| 重复变体 | 比较素材引用、时间与文案；不同名字或行顺序不会被当成不同内容。不是视觉相似度或缓存命中证明 |
| 新批次 | 前后端均限制 1–20 变体；历史大批次继续保留和查看，复制时需删减到 20 以内 |
| 草稿与版本 | 未保存草稿阻止检查；定位问题时保留离开确认；旧 revision 返回 409；重复保存沿用原幂等键 |
| 报告 | `pi-studio.preparation@1`，带 revision、检查时间、来源快照、问题定位及待验证项；`canExecute` 恒为 false |

检查是只读操作，不写任务状态、不更改 revision、不触发模型或媒体制作。检查时仅核对文件存在与大小，报告中的哈希是登记值，`hashVerified: false`；重新导入去重时才流式计算现存文件哈希，修复缺失、截断及同大小内容损坏。恢复文件不增加素材记录，不改冻结方案或批次。

本地导入继续保留原来的 512 MiB 格式/大小范围；首版检查不删除旧素材，也未把 100 MB 输入声明为已经可在 Worker 处理。实际时长 ≤60 秒、编码、分辨率、全片解码、字体呈现、音画同步、模型效果、云端资源与费用都未在该检查中验证。规则无误只表示已知字段符合要求。

## 文件与接口

- `packages/remix/preparation.mjs`：独立纯检查器；不依赖 Node 文件系统或外部服务。问题展示最多 500 项，总数仍完整统计。
- `packages/remix/index.mjs`：读取当前文件状态；只读检查、同项目来源批次查找、冻结快照复制、原素材 ID 修复。继承既有版本冲突和请求幂等保护。
- `apps/web/remix-preparation.js`：检查面板、问题导航、报告下载、失败重试。
- `apps/web/remix-batch-editor.js`：批次编辑器、版本复制、数量限制、来源提示；从旧的单文件 UI 中独立拆出。
- `apps/web/remix.js` / `style.css`：接入方案和批次页、修复上传反馈、深浅主题与窄屏布局。
- SaaS API、本地 application、静态文件白名单与 SaaS 构建同步接入。桌面继续使用共享文件，未重新打包或宣称原生桌面验收。

`POST /api/remix/:id/check` 接收 `{revision, batchId?}`，返回只读检查报告。SaaS 沿用服务端会话和空间归属校验，越权 404、未登录 401。

`POST /api/remix/:id/batches` 增加可选 `sourceBatchId`。服务端只允许本项目已有批次，使用其 `plan`，创建新的批次与变体 ID；客户端传入各变体覆盖值。遗漏来源时仍基于当前方案创建。来源 ID 纳入幂等指纹。
