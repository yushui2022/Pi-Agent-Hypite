# 单用户最小闭环：单条真实复刻出片（2026-10-20）

## 为什么是这个切片

"多用户复刻出片"拆开是四个独立能力，当前只有半个：

| 能力 | 现状 |
|---|---|
| ① 参考视频理解（Pi + 模型） | 未实现，模型在实验里是 `disabled` |
| ② 网页方案 → 可执行工程 | 契约不匹配，本次补齐映射层 |
| ③ 渲染出片 | 本地 workerd 通过，云端关口未过 |
| ④ 多用户隔离/并发/计费 | 隔离有，制作链路无 |

顺序不能倒：**①②不通，④只是空按钮**。本清单只锁定"单账号 + 单条 + 真实素材 + 15 秒成片"从网页点出来这一件事。

明确不做：多用户并发、队列调度、计费配额、公网部署、通用剪辑。这些都在本闭环验收通过之后再排。

## 判定为"通过"的条件

必须**同时**满足以下四层，且证据可复核。任何一层缺失都只能记为"未通过"，不能合并成"基本完成"。

## 需要你提供的输入（缺一项，L3 无法开始）

1. **一条真实参考视频**（H.264 MP4，< 100 MB，< 60 秒）
2. **至少一条替换素材**（视频或图片）
3. **模型服务与预算**：用哪个供应商、单条可接受成本上限。参考分析必须真实调用模型，不能再用 fixture 顶替
4. **字体授权**：当前用生成的 Noto SC 子集，商用前需确认许可范围

在 1–3 到位前，L1/L2 可以继续推进，L3 只能保持 `execute` 返回 409。

## 失败与降级处理

- 云端 P0 不通过（内存/CPU/费用任一超限）→ 回到 `docs/workers-execution-plan.md` 的降级分支评估，**不擅自切换容器或外部平台**
- 真实素材无法 8 MiB 内处理 → 这是已知架构缺口，需先解决分片/降采样，不得用合成素材冒充通过
- 模型调用失败 → 记录真实失败与原样输入，不得回填模板文案冒充分析结果

## 与本项目既有约定的关系

- 遵循 `AGENTS.md`：模拟通过不得标记为真实制作完成

- 验收记录写入 `docs/verification.md`，进度写入 `docs/progress.md`
