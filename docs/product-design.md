# 多账号内容生产工作台：功能与页面设计

## 最新范围纠正：以批量复刻工作流为核心

2026-10-18 用户进一步明确：主要任务是导入参考视频及其他素材，指定替换内容，建立多个制作批次，执行替换制作，并在对应模块集中查看成品。账号不是生产流程的必要入口；200 个账号仅是历史规模测试，不是业务目标或固定约束。下文先前“账号/商品驱动”的路径降为可选应用场景，实施优先级以本节为准。

### 主要工作路径

新建复刻项目 → 导入参考视频 → 手工标注/分析参考结构 → 导入替换素材 → 定义保留项与替换项 → 建立多个批次及变体 → 核对映射并小样试制 → 执行批次 → 成品预览、返工与导出。

“复刻”默认指参考结构与表达方式后改编制作，不预设可以对任意视频直接精准换物、换人或无损替换。参考拆解、重建剪辑、文字替换、配音、生成式换物等是不同执行能力，应分别确认实现与供应商支持。

### 核心模块重新组织

| 模块 | 细分功能 | 页面形式与输出 |
| --- | --- | --- |
| 复刻项目 | 项目名称、目标规格、参考版本、多个制作批次 | 项目列表 → 项目工作区；身份不依赖账号 |
| 参考与素材 | 本地视频/图片/音频导入、预览、文件检查、参考时间段、素材分组 | 素材网格 + 预览；大文件存 G 盘；无自动分析时允许手工标注 |
| 替换方案 | 按镜头/时间段列出原内容、保留项、替换类型、候选素材、文案/配音及执行方式 | 替换映射表 + 视频预览；明确缺素材、冲突、不支持能力；可保存方案版本 |
| 制作批次 | 同一项目建立多个批次，每批指定素材组合、语言/文案/规格、变体数量及可选账号 | 批次列表和逐条变体预览；不默认所有素材做笛卡尔积；执行前显示具体任务及总量 |
| 执行与异常 | 试制、批量提交、阶段进度、暂停新提交、失败补做、状态核实 | 任务队列；保留成功阶段和产物；缺 API 时停在准备状态，不伪造替换完成 |
| 成品库 | 项目/批次归属、预览、版本、来源方案与素材、审核、返工、导出 | 视频缩略图网格 + 播放详情；按项目/批次/状态筛选；失败任务留在异常列表，不冒充成品 |

对象关系：复刻项目包含参考素材、替换方案版本和多个批次；批次包含明确的变体任务；每条任务关联执行记录与作品版本；账号只是可选标签或交付对象。成品同时能从全局成品库和所属批次找回。

示例仅用于解释：同一参考视频，A 批使用商品素材甲与中文文案，B 批使用商品素材乙与英语文案。每批先列明具体替换组合，再试制一条，确认后处理剩余条目。系统不擅自假设每个账号必须产出固定条数。

## 1. 本轮要纠正什么

主要使用者是同时为数百个账号准备内容的运营人员。桌面连续操作是主要情境；多人协作属于后续能力，目前只有本机工作空间。

核心任务：为一组账号安排某个商品的一批内容，明确每条差异，补齐素材，执行制作，处理异常，审核版本，按账号交付。成功应当是找得到、能核对的交付文件，而非建好了多少目录。

已有测试证明账号与批次数据可以保存、600 条任务可以建立。它们尚不能证明批量生产流程完整或界面好用。此次用户反馈说明上一轮只完成了基础能力，没有充分设计业务组织和使用方式。

### 已核对的问题

| 具体问题 | 代码证据 | 对使用者的影响 | 本次设计决定 |
| --- | --- | --- | --- |
| 账号列表旁常驻新增表单；详情就是同一组输入框 | apps/web/bulk.js / mountAccounts | 可以录入，但难以判断哪些账号适合本批、哪些资料不足 | 账号表格 + 独立详情；生产规则、关联内容、缺失项各有位置 |
| 分组是自由文本；没有独立标签筛选、批量修改和导入错误清单 | packages/bulk 与 bulk-format.js | 200 个账号仍需逐一维护，导入依赖固定列顺序 | 导入向导、字段映射、分组视图、明确范围的批量动作 |
| 批次只有统一要求与每号数量，差异靠第几条的文字提示 | bulk.js / mountBatchNew；packages/bulk | 600 条建档可能仍是相同需求，没有内容分配策略 | 增加可编辑的内容分配矩阵，再固定计划 |
| 批次详情只有建档数量和任务清单 | bulk.js / mountBatch | 无法回答哪些缺素材、哪些失败、哪些待审核 | 批次成为生产主入口，按阶段和异常组织任务 |
| 商品事实和素材路径保存在任务文本中 | app.js / detail | 重复录入、事实更新无法追踪、路径不等于可用素材 | 商品和素材成为独立对象，任务固定所用版本 |
| 单任务页把需求、Agent、检查分散堆放 | app.js / detail、agent.js | 操作者需要理解技术工具，仍不知道下一步业务动作 | 任务详情按需求、脚本、素材、制作、版本组织 |
| 服务页面展示接入说明，未形成配置、验证、使用反馈闭环 | app.js / services；packages/application | “已接入”和“能制作”仍容易混淆 | 能力分层显示，失败与补配入口对应真实原因 |

以上是源码核对与用户反馈；本轮没有新增用户可用性测试，也不声称重新完成了原生界面验收。

## 3. 对象关系与范围

| 对象 | 负责什么 | 与其他对象的关系 |
| --- | --- | --- |
| 账号 | 内容受众、语言、表达及输出规则 | 属于分组；被批次选中后产生规则快照 |
| 商品 | 可确认的事实、卖点及禁用表达 | 关联素材；被批次引用固定版本 |
| 素材 | 图片、视频、声音、参考及可用性记录 | 可以复用；记录被哪些任务版本使用 |
| 制作方案 | 可复用的脚本结构、风格、镜头及参数规则 | 有版本；与账号规则一起生成分配方案 |
| 批次 | 一次生产目标、范围、数量、差异安排和交付要求 | 包含任务，聚合进度，不代替任务状态 |
| 内容任务 | 某账号的一条具体内容目标 | 关联账号、批次、商品、素材和制作方案版本 |
| 执行记录 | 一次实际 Agent、生成或渲染尝试 | 一个任务可有多次执行；记录请求和错误 |
| 作品版本 | 一次可审阅的输出 | 对应文件、来源执行、审核结论；旧版本保留 |
| 交付记录 | 被选版本的导出清单和结果 | 关联批次与账号；不代表已发布到平台 |

Pi 作为任务编排和工程操作的底座；Hypit 承担其实际支持的制作工程能力。复刻需求应先成为参考分析与改编方案，再进入工程和产物流程。不能因源码存在便宣称“视频分析、自动复刻、批量渲染”全部可用。业务层持有任务与版本，底层运行结果通过适配器接入。

当前单人本地版本暂不加入平台账号登录、自动发布、团队权限后台、投放、热点采集或分布式集群。这些不是本次生产闭环的前置条件。

## 4. 导航与完整路径

建议顶层导航按工作场景分组，而不是每新增一个技术能力就加一个入口：

| 导航组 | 一级页面 | 页面内的次级结构 |
| --- | --- | --- |
| 工作 | 工作概览 | 需要处理、进行中的批次、最近结果 |
| 工作 | 生产批次 | 批次列表 → 分配计划 / 任务 / 异常 / 交付 |
| 工作 | 内容任务 | 全部 / 待准备 / 制作中 / 待审核 / 异常；共享任务详情 |
| 资料 | 账号管理 | 账号表格、分组筛选、账号详情、导入流程 |
| 资料 | 商品与素材 | 商品目录 / 素材库 / 参考库 |
| 资料 | 制作方案 | 模板及版本；不单独开“提示词管理”主导航 |
| 系统 | 设置 | 制作服务、预算规则、存储、运行诊断 |

审核作为任务列表中的专用视图和详情工作区；生产队列作为跨批次任务视图；交付以批次为入口。它们有独立业务模型，但不必各占一个顶层导航项。未实现页面暂不放到正式导航制造完整产品假象。

主要路径：选择商品 → 选择账号 → 分配内容方向与数量 → 检查资料和规则 → 保存计划 → 小批试制 → 审核试制结果 → 执行剩余任务 → 处理异常 → 审核 → 按账号导出。

无素材/API 时仍可完成：账号整理 → 商品事实维护 → 手工内容分配 → 缺失项检查 → 计划保存与准备清单导出。停止在“待制作”，保持下一步明确，不虚构后半段结果。

### M01 工作概览（未实现）

目的：打开工作台后知道今天应先处理什么。

| 子模块 | 功能与呈现 | 关键操作与结果 |
| --- | --- | --- |
| 待办摘要 | 缺资料、执行异常、待审核三个可点击数量；只统计真实状态 | 点击进入已筛选列表；没有该能力时不展示虚假 0 |
| 批次推进 | 紧凑表格：批次、目标数、待准备/运行/审核/交付数、最近活动 | 打开批次并保留来源，不用一个百分比混合所有阶段 |

### M02 账号管理（已有基础，需重做信息组织）

| 子模块 | 功能与呈现 | 关键操作与结果 |
| --- | --- | --- |
| 账号总表 | 列：选择、名称/编号、分组、目标市场、语言、规则完整度、状态；次要列可收纳 | 搜索、组合筛选、排序、分页、保存本机视图；进入详情后返回恢复位置 |
| 分组与标签 | 左侧分组或筛选栏；分组为主要归类，标签支持交叉分类 | 批量移动分组、加/去标签；预览受影响数量；不默认全量生效 |
| 内容定位 | 详情“定位”：受众、内容领域、人设/语气、禁用表达、参考样例 | 分组字段编辑；完整度列出缺哪些，不用无依据的综合评分 |
| 制作规则 | 详情“规则”：默认语言、画幅、时长范围、字幕、配音、品牌元素 | 展示规则来源和覆盖项；已有批次快照不随修改静默更新 |
| 关联内容 | 详情“内容”：参与批次、具体任务、已审作品 | 按状态筛选并跳转，用户能看出该账号已经安排了什么 |
| 导入向导 | 粘贴/文件读取 → 列映射 → 全量校验表 → 新增/跳过/冲突预览 → 结果 | 错误含行号、字段、原因；下载错误清单；修正后只补未成功项 |
| 批量编辑 | 选择后出现操作栏，明确“本页 40 / 已选 120 / 全部匹配 200” | 默认只改勾选字段；空值的保留/清除分开；结果说明成功与冲突项 |
| 停用与归档 | 停用阻止新分配，历史内容仍可查 | 待执行计划中的停用账号要求核对；不直接删除历史记录 |

账号详情采用完整页面与标签页；抽屉仅承担快速查看，不塞完整长表单。默认右侧不常驻空的新增表单。

验收：导入含重复号、缺语言、长名称的 200 行；修正失败行；批量改 20 个账号且不影响未选项；旧批次仍显示旧规则。

| 方案目录 | 按产品演示、对比讲解等用途组织；名称、适用条件、版本 | 复制为新方案；不把模板存在标成能执行 |

| 表达与输出 | 画幅、字幕、配音、视觉约束和素材槽位 | 保存必填变量、默认项、缺少条件；执行前展开最终有效值 |
| 差异规则 | 显式定义开场、卖点顺序、镜头或语气等变化维度 | 批次中预览每条分配；“第 1/2/3 条”不算差异；冲突标出 |
| 工程映射 | 高级区展示与 Hypit 工程入口及版本的对应 | 模板参数校验和真实检查分开；运行能力逐项验收 |

规则优先级提案：任务显式覆盖 > 批次覆盖 > 账号规则 > 方案默认。商品事实和硬性限制不得被普通覆盖跳过；冲突阻止进入执行并列出字段来源。

验收：同账号 3 条至少有明确的人工确认差异；不能把随机种子不同宣称为业务内容不同。

### M06 批次策划（已有建档，缺分配设计）

新建采用可返回的分步流程，右侧保留数量与缺失摘要；草稿自动保存需有实际落盘回执。

| 步骤 | 内容与呈现 | 可保存的输出 |
| --- | --- | --- |
| 目标 | 批次名称、商品版本、用途、交付日期、输出要求 | 批次草稿；日期只是交付要求，不等于自动定时执行 |
| 账号 | 账号表格、多条件筛选、分组选择；显示停用/缺规则项 | 固定选中 ID 与当时版本，显示跨页选择范围 |
| 内容分配 | 一行一条内容：账号、语言、方案、开场、卖点、参考、数量/序号、缺失项 | 可分组折叠、批量填充、单条覆盖、调整数量；生成可审阅矩阵 |
| 资料检查 | 按任务列出缺商品事实/素材/规则/服务等阻塞 | 选择补齐、移出本批或保留待准备；不能默默跳过 |
| 核对计划 | 账号数、任务数、差异分布、所用版本、试制范围、费用状态 | 保存计划与快照；明确建档不收费、制作是否可能收费 |

确认后打开批次详情，包含“概览、内容计划、任务、异常、交付”。概览的每一个阶段计数都能进入对应任务，不用只能看的大数字卡片。

已确认计划修改：新增修订；已执行任务保留原输入；新内容创建新任务。确认时版本冲突显示差异，不能覆盖其他窗口的新修改。

验收：200 个账号每号 3 条，能检查全部 600 条分配；调整某组语言/数量不影响其他组；刷新回到草稿和筛选；移除账号后总数与任务列表一致。

### M07 内容任务与制作工作区（已有需求/Agent/检查基础）

| 子模块 | 呈现与操作 | 完成依据 |
| --- | --- | --- |
| 任务列表 | 行包含账号、商品、批次、内容方向、当前阶段、阻塞原因；保存常用筛选 | 所有行指向稳定任务 ID，返回保留查询与滚动 |
| 需求 | 分组摘要和编辑入口；显示继承值、覆盖值、来源快照 | 保存版本及回执，修改已执行需求时产生新修订 |
| 脚本/镜头 | 中央分段编辑区，侧边关联素材与检查项 | 手工编辑可独立保存；Agent 建议与已采用内容分开 |
| 制作 | 当前执行阶段、控制动作、等待输入；详细日志折叠 | 以事件和实际工程为依据，不把对话文字当执行成功 |

Pi 对话服务于当前任务，有输入上下文摘要和采用变更记录。不要要求运营人员先输入工程路径才能进入正常内容流程。工作区优先给脚本、素材、预览留空间，Agent 面板按需展开。

### M08 生产队列与异常处理（未实现，现有暂停只控制建档）

| --- | --- | --- |
| 执行准备 | 批次选中任务，展示依赖、供应商、并发规则和试制数量 | 条件不齐列出每条原因；不要一次启动数百个 Agent 进程 |
| 队列 | 表格：任务、阶段、供应商、开始时间、最近事件、重试次数 | 排队/执行/等输入/失败/待核实分开；只展示可依据事件计算的进度 |

| 中断恢复 | 启动时重建运行视图与依赖状态 | 崩溃后未知项进入待核实；进程消失不代表远端已停止 |

## 6. 状态与操作统一约定

### 不把不同对象的状态混在一起

| 对象 | 目标状态/事实 | 转换条件 |
| --- | --- | --- |
| 批次计划 | 草稿 → 已确认 → 已修订/归档 | 用户确认范围并固定输入；制作计数从任务聚合 |
| 建档过程 | 计划中 → 建档中 → 暂停/失败/已建齐 | 沿用现有实现；不把 ready 改解释成制作完成 |
| 内容任务 | 待准备 → 可制作 → 排队 → 制作中 → 待审核 → 已通过 → 已交付 | 准备检查、真实执行、产物、审核和导出各自提供依据 |
| 执行尝试 | 排队、运行、等输入、停止请求中、已停止、失败、待核实、成功 | 停止与成功以运行及供应商证据确定 |
| 作品版本 | 待审核、需返工、已通过、已替代 | 审核针对版本；新版本不会自动通过 |

任务可从返工回到待准备/可制作；部分阶段依任务类型跳过，但需显式记录理由。批次的 600 条可以同时处于不同阶段，不用“已完成 80%”掩盖差异。

### 动作行为

| 动作 | 前置条件与范围 | 反馈、失败及恢复 |
| --- | --- | --- |
| 批量修改账号 | 显式选择 ID 与字段 | 显示成功/冲突数；保留失败项选择，不覆盖冲突版本 |
| 保存内容计划 | 账号/商品/方案版本、分配项合法 | 保存回执后才显示已保存；超时查询原请求，保留草稿 |
| 提交试制 | 输入齐全、能力可用、范围与费用规则清楚 | 生成执行 ID；请求结果未知先核实，不重复新建提交 |
| 暂停生产 | 指定批次或队列范围 | 明确“停止新任务”与“请求终止正在运行任务”两个动作 |
| 重试失败 | 只选择已明确失败的执行 | 保留成功阶段，说明重跑范围及可能新增费用 |
| 审核通过 | 有可核对作品版本 | 审核绑定版本；重复操作幂等，冲突重新加载 |
| 导出交付 | 选定通过版本及有效路径 | 文件级结果与清单，失败仅补缺项 |

共用状态：首次空数据提供下一步；无搜索结果提供清除筛选；加载保留原上下文；读取失败提供重试；保存失败保留输入；离开未保存页有保护；断联显示待核实。异常不只给一条短暂消失的提示。

## 7. 页面呈现规则与代表布局

定位为长时间批处理的专业桌面工具。沿用当前品牌和双主题；标题约 22–26px，正文/控件从 13–14px 开始评估；数字对齐，固定行操作位置。深浅主题成对定义文字与背景，错误使用文字与图标共同表达。最终尺寸要经真实窗口验证。

| 页面 | 主体布局 | 常驻信息 | 按需显示 |
| --- | --- | --- | --- |
| 账号管理 | 筛选栏 + 高密度表格 | 分组、语言、完整度、状态、选中数量 | 导入向导、批量修改、详情 |
| 商品与素材 | 商品列表/素材网格 + 详情预览 | 类型、可用性、来源商品 | 文件技术信息、完整引用历史 |
| 批次计划 | 分步入口 + 分配矩阵 | 账号、内容差异、缺失、总量 | 每条覆盖、规则来源、完整计划检查 |
| 批次详情 | 标题/状态摘要 + 标签页 + 任务表 | 批次目标、真实阶段数量、异常入口 | 全部事件、快照细节 |
| 制作/审核 | 对象队列 + 中央脚本或预览 + 上下文面板 | 当前任务/账号/版本、核心动作 | Agent 日志、工程工具、历史版本 |

批次详情示意（目标结构，不是已实现截图）：

```text

200 个账号 · 600 条计划 · 输入版本及最近保存时间
待准备 N | 可制作 N | 制作中 N | 待审核 N | 已通过 N | 异常 N

筛选：账号组 / 语言 / 阶段 / 缺失项        搜索      列设置
□ 账号       内容方向       方案/差异       当前阶段       下一步
□ US-01      产品演示       开场 A         缺演示素材     补素材
□ ES-02      场景讲解       开场 B         待确认脚本     打开脚本
已选 N 条（跨页）               [分配素材] [调整方案] [移出本批]
```

示意行是设计样本，不能放入真实工作空间假装生产记录。无 API 时可制作/制作中等依赖能力的区域显示对应不可用原因或不展示。

960px 左右窄窗口优先收起筛选和辅助面板；复杂矩阵允许明确的横向滚动，保留账号列；手机提供逐条查看/审核，不承诺完整批量编辑体验。键盘选择、焦点、弹层关闭返回、缩放和长中文/英文都属于验收内容。

## 8. 实施顺序与代码归属

不要一次铺满所有页面，也不要把此规划写成几十个不可用按钮。每阶段完成正常与恢复路径后才进入下一阶段。

| 阶段 | 完整业务切片 | 文件/模块（新目录为计划） | 验收门槛 |
| --- | --- | --- | --- |
| A 账号与资料整理 | 导入校验 → 分组维护 → 查看内容规则 → 批量修改 → 返回原视图 | 拆分 apps/web/bulk.js 为 accounts 页面/导入/详情；共享表格、筛选、选择组件；packages/bulk 兼容扩展 | 200 行含错误样本、跨页选择、冲突恢复、旧快照不变 |
| B 计划准备闭环 | 商品事实 → 手工方案 → 账号内容矩阵 → 缺失检查 → 保存/恢复 → 导出准备清单 | 新 packages/catalog、packages/planning；apps/web 对应页面；packages/application 共用接口 | 无外部 API 可完成 600 条分配与清单导出；旧任务可读 |
| C 素材与单条试制 | 本地素材 → 参考改编方案 → Pi 工程 → Hypit 检查/制作 → 真实作品 | packages/assets、现有 workers/agent 与 Hypit adapter、任务工作区 | 有真实输入、模型及视频服务后，用小任务验证产物和失败恢复 |
| D 批量生产 | 小批试制通过 → 排队执行 → 限流/暂停/恢复 → 异常补做 | packages/production、执行事件和费用记录；队列视图 | 不重复提交、不会把未知判失败；实际供应商小批验证再扩量 |
| E 审核交付 | 审核 → 时间点反馈 → 新版本 → 通过 → 按账号导出 | packages/reviews、packages/delivery、作品与审核工作区 | 文件、版本、审核及导出数量一致，可恢复部分导出 |

布局/主题由 apps/web/index.html、style.css 的明确作用域负责；通用控件逐步提取到 apps/web/components；页面控制与数据请求分开；HTTP 与桌面继续通过 packages/application 复用。Pi/Hypit 具体改动以阶段 C 的真实能力缺口决定，不为页面重排盲目修改上游。

现有数据优先兼容：account ID、batch ID、job ID 保留；新增结构有 schemaVersion；旧自由文本保留为旧版规则；历史批次照原快照读取。单条手建任务允许暂未关联账号，但显示“未关联账号”，不能按相同名称自动合并。

数据库迁移是后续独立工程决定：生产队列前需要评估 SQLite、事务、索引与单实例写入。当前文件存储的单写入假设不能直接扩成多人并发。切换存储需备份、数量/哈希核对和回退入口，不与视觉整理同时强迁移。

## 9. 验证样本、风险与未知

| 验证层 | 本轮结果 | 后续应收集的证据 |

真实风险：
