# 复刻工作流升级：项目、素材与多批次计划

2026-10-18。已交付可持久化的准备流程，未交付真实自动替换制作。

## 使用路径

默认首页及侧栏“复刻项目” → 新建项目（不填账号） → 多选本地参考视频/替换素材 → 选择媒体播放/查看 → 用作参考 → 标注替换位置 → 保存方案 → 创建多个批次及逐条变体 → 展开核对与导出计划。

项目内有参考与素材、替换方案、制作批次、成品库四个区域。成品库当前显示真实的零产物状态与返回批次入口，不提供模拟成片、假执行进度或可点击但无实现的生成按钮。现有账号批次仍独立保留。

## 实现内容

- 媒体导入：浏览器/桌面文件选择，多文件依次传输；每片 32 KiB，保持 HTTP/stdio 帧限制；真实接收字节进度、取消、已完成保留、错误后重选复用。
- 支持扩展名 MP4/WebM/MOV、PNG/JPEG、MP3/WAV；检查常见文件头，不等于完整解码/编码兼容验证。单文件 512 MiB；导入前检查存储容量并留 64 MiB 余量；没有安装新媒体依赖。
- 文件复制到配置 dataRoot/.remix/<project>/，不依赖用户原文件后续所在位置。SHA256 去重，原文件不修改。按现有配置，数据和临时测试均在 G 盘。
- 预览通过仅绑定 127.0.0.1 的随机端口和随机令牌提供，支持 Range/HEAD；只访问项目登记的媒体 ID，不提供任意路径读取。退出关闭媒体服务。网页和桌面的 CSP 仅为本地媒体增加 img/media 来源。
- 替换方案：参考视频、保留要求、命名位置、开始/结束秒数、图片/视频/音频/文案类型、默认素材或文字；最多 100 项，校验类型与时间先后。可暂缺替换素材，批次明确标注待补。
- 多批次：每批明确列出变体和覆盖值；不自动排列全部素材。每项目最多 100 批，每批最多 200 变体；这是当前工程限额，不是账号规模目标。保存固定方案快照，后改方案不回写旧批次；请求 ID 防重复提交。
- 可展开每条变体的素材映射，导出 JSON 制作计划（不含媒体文件，不是成片）。手工需求不使用账号绑定。
- 为避免桌面帧超限，所有前端 JSON 提交预检 60,000 字节；超限提示拆分。单项目元数据当前上限 2 MiB，防止展开快照造成大响应。
- 切换标签和离开项目有未保存保护；导入期间阻止离开和更换参考，允许取消。重启/刷新后重读已保存项目、方案、素材和批次。

## 代码

packages/remix/index.mjs 管理项目、素材、方案和本地媒体服务；packages/application 统一接入 HTTP/桌面业务；apps/web/remix.js 提供工作区；app.js、workspace-state.js、index.html 接入导航；style.css 添加局部布局；api.js 预检请求大小；桌面配置增加本地媒体 CSP。test/remix.test.mjs 验证新业务契约。

## 明确的缺口

- 参考拆解目前手工填写；无镜头检测、自动语义分析、换物/换人、字幕烧录、配音替换或实际渲染。Pi/Hypit 暂未消费这一套新计划；需要后续适配并用真实素材验收。
- 时间段只检查合法性，尚未提取并校验参考视频实际时长、帧率或重叠策略；这些需在执行前补齐。
- 成品库是项目归档入口和真实空状态，尚无产物写入、版本审核、返工或成片导出链路。不得宣称已完成成品管理。
- 不支持导入断点续传；运行时正常退出会清理活跃 .part，强制崩溃可能留临时文件或尚未登记文件，尚未实现恢复/清理工具。不要当作用户原素材自动删除。
- 512 MiB 是校验上限，未用此体积实测；分片 IPC 对大视频可能较慢，后续需要流式导入及长期吞吐测试。
- 单运行时写入文件；未增加多进程锁或数据库。项目和批次尚无删除/归档/批次修订工具；这些不应以删除文件的隐藏操作替代。

下一步先选定一种明确的替换执行方式，完成“一个计划 → Pi/Hypit/媒体执行 → 一个真实文件 → 可预览作品版本”，再扩大批次执行、恢复和交付。
