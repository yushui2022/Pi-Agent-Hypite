# 批量生产：首个业务切片

2026-10-18。业务优先级调整：先实现账号资料和批次任务编排，再推进安装包完善。素材库、实际生产队列、审核和交付仍按后续阶段接入。

## 目标与范围

录入/粘贴导入数百个账号 → 选择账号、填写商品与要求、每账号数量 → 保存可审阅的批次快照 → 确认建档 → 查看进度、暂停/继续 → 打开独立任务。以 200 个账号 × 3 条 = 600 个真实任务验证。

本轮“批量”指需求与工程目录建档，不执行模型、视频生成或渲染。账号资料不是平台登录凭据。素材引用库与执行队列另行实现，不用建档进度冒充制作进度。

## 文件与执行顺序

1. packages/bulk：账号校验、原子文件存储、版本冲突、导入去重；不可变账号快照与批次清单。
2. packages/jobs：按预分配 ID 幂等初始化任务，持久化批次/账号关联。
3. packages/application：共享 HTTP/桌面入口；后台逐条建档、暂停、恢复和退出清理。
4. apps/web/bulk.js：账号资料、Excel TSV 粘贴导入预览、账号筛选、批次确认与分页任务列表；沿用主题和编辑保护。
5. test/bulk.test.mjs：规模、重试、崩溃窗口、快照、停用与冲突验证；实际界面操作验收。

## 契约与限制

- 当前单个工作台运行时拥有写权限，禁止多个独立进程写同一数据目录。配置保存在 dataRoot/.bulk，批次任务仍在原 dataRoot。
- 账号唯一键为 accountKey（内部账号编号或 handle），大小写不敏感；导入已存在编号只跳过，不覆盖现有设置。编辑使用 revision 防止覆盖。
- 单次导入最多 200 行，UI 分成小块传输；初版最多 1000 个账号。批次最多 2000 条任务，每账号 1–20 条。
- 批次确认前固定账号快照与任务 ID；重复提交相同 requestId 返回原批次，不同内容使用同一 requestId 返回冲突。
- 建档按单任务串行，不启动大量 Pi 进程；暂停在当前任务写完后生效。重启不自动继续，明确显示暂停并由用户恢复。已有任务不重新覆盖。
- 真实生产阶段还需加入供应商限流、预算、资源池、付费提交幂等、素材复用、审核与按账号导出，不能直接复用本轮“已建齐”状态作为成片成功。

## 验证与风险

验证账号导入/编辑/停用、重复编号、非法输入、创建批次后修改账号不影响快照、重复确认不多建、暂停恢复、任务已落盘而进度未落盘时恢复、600 个任务的数量和账号语言对应。用真实 UI 验证导入预览、批次确认、打开任务及未保存保护。

风险：文件存储并非数据库事务，采用持久清单和固定 ID 弥补进度写入中断；多进程并发和磁盘满仍需后续数据库/单实例方案。较大列表先分页渲染，后续生产事件和检索再迁移 SQLite。外部 API 尚未提供，不能验收批量视频产出吞吐量。
